# BIMBOY-Platform

## Overview

BIMBOY is a digital BIM management platform built on the
[That Open](https://docs.thatopen.com) ecosystem. It brings models, documents, coordination
and GIS data for construction projects into one web app.

Roadmap:

1. BIM model viewer (IFC / FRAG)
2. Clash detection (BCF import)
3. Document management (revisions)
4. Drawing management (CAD / PDF)
5. BIM + GIS (Cesium 3D Tiles)

The app also has AR (WebXR) viewing and an IoT tab for devices and live readings.

## Tech stack

- **React 19**, **@tanstack/react-router** (file-based), **Zustand v5**, **Tailwind v4**
- **TanStack Query** for async data, **Zod v4** for schemas
- **That Open Engine** `@thatopen/components` + `@thatopen/ui` **v3.4.x**, **Three.js** ^0.182
- **Cesium** + **3d-tiles-renderer** for GIS
- **Supabase** for auth, database and storage (migrations in `supabase/migrations/`)
- **Vite 7** + TypeScript ^5.2, ESLint, **Playwright** end-to-end tests
- **Cloudflare Workers** static assets for hosting (`wrangler.jsonc`)

## Running locally

Create `.env.local` with the Supabase project values:

```bash
VITE_SUPABASE_URL=...
VITE_SUPABASE_PUBLISHABLE_KEY=...
# Optional, development only:
VITE_DEV_AUTO_LOGIN_EMAIL=...
VITE_DEV_AUTO_LOGIN_PASSWORD=...
```

Then:

```bash
npm install
npm run dev              # Vite dev server
npm run build            # Production build into dist/
npm run preview          # Serve the built app
npm run lint             # ESLint
npm run test:e2e         # Playwright tests (test:e2e:ui for the UI runner)
```

## Deploying

Cloudflare Workers deploys `main` automatically from git. SPA routing comes from
`wrangler.jsonc` (`not_found_handling: single-page-application`). Set the `VITE_*` values as
**build** variables in Worker Settings → Build → Variables and secrets; the static-assets
Worker rejects runtime variables.

## Developing

- Read `CLAUDE.md` first: architecture layers, where each kind of file goes, naming, and hard
  constraints.
- Area detail lives in `docs/feature/`; the reasons behind decisions live in `docs/adr/`.
- Keep `@thatopen/*` on v3.4.x and check Three.js / web-ifc peer versions before upgrading.
- Work on a feature branch; changes reach `main` through review.
