Removed: native <select> element in EditableSelectField — replaced by the custom listbox popup.

Removed: blur-to-save in EditableTextField — commit now only happens via explicit ✔️ (or Enter for single-line).

⚖️ Pros & Cons

ProsCons
Explicit confirm/cancel removes the "did clicking away just silently save that?" ambiguity in the current blur-to-save text fields.Behavior change: users used to click-away-to-save must learn the new explicit-✔️ habit; a stray click that used to save now does nothing until confirmed.
Matches the requested Notion/Linear-style status picker exactly (colored bar, highlighted row, checkmark) using colors already defined in clashDisplayHelpers.ts — no new tokens.Hand-rolled listbox (no Radix/Headless UI in this repo) has weaker keyboard support than a library component — no arrow-key roving nav, click/Escape only.
Zero new dependencies — everything built with existing lucide-react icons and Tailwind tokens already used in this file.No portal for the popup, so it can be visually clipped if opened very near the bottom of a scrollable panel (accepted edge case, same as other non-portaled popovers here).
Select fields keep today's save-on-click simplicity (no redundant ✔️/❌ added there) — smaller behavior change than doing it everywhere.Two distinct dropdown trigger states now exist (view-mode pill vs. edit-mode bordered box) — slightly more visual states to keep in sync than a single restyled control.
