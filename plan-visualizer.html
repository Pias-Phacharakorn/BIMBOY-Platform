⚖️ Pros & Cons

ProsCons
Purely additive: model still loads 2m-in-front, so a decode failure or no-QR degrades to today's exact behavior — nothing that works is lost. Reverses two just-shipped decisions (no-1:1-placement note + the drag-to-rotate turntable from 6 commits ago); the turntable code is deleted.
In-session raw camera access gives the XR camera pose at decode time → clean world-lock; sidesteps the doc's camera-handoff and 90°/180° frame-mismatch unknowns. Raw Camera Access + XRWebGLBinding + readPixels readback is real, device-specific plumbing that can only be fully validated on an Android Chrome device — not desktop.
Lightweight homography PnP + jsQR (decoder-only) keep the Cloudflare-static bundle lean — no ~8MB opencv.js. Hand-rolled planar-pose math needs careful testing; homography decomposition is sensitive to corner-detection noise / motion blur.
Logic isolated in a testable pure util (qrPose.ts) + a hook (useArQrAnchor.ts) per AGENTS.md layering; ArModelViewer stays a composition of hooks. Fixed global QR_PHYSICAL_SIZE_M means every printed code must be one standard size until a lookup-key payload is added later.
