Removed: hand-rolled storey math — no getItemsOfCategories/getItemsData composition; no hardcoded drawing.three.position.set(0,1.2,0)/drawing.far = 4 (now per-level, derived from each storey's plane and floor-to-floor spacing).

⚖️ Pros & Cons

ProsCons
Uses ThatOpen's own createFromIfcStoreys() instead of hand-rolled category/attribute querying — gets the georeferencing height offset (model.getCoordinates()) correct for free, which a manual version would likely have missed. createFromIfcStoreys() assumes an IFC-derived model (per ThatOpen's own docs) — models converted from non-IFC schemas, or IFC files without properly authored IFCBUILDINGSTOREY/Elevation attributes, will return zero levels. No fallback UI state for "no storeys found" is in scope for this round (falls back to an empty list, not a crash) — worth flagging to users if it comes up.
Lazy per-level projection (cheap discovery eagerly, expensive projection only on first click, cached after) keeps tab-activation fast regardless of storey count, while still showing the full real level list immediately. Per-level `TechnicalDrawing` + projected geometry stays cached in memory for the whole session once visited — on a model with many storeys and heavy geometry, clicking through most of them could accumulate meaningful memory before the tab deactivates and the whole cache is torn down.
±0.3m elevation-bucket merge means multi-discipline models (Architecture + Structure) collapse to one row per physical floor instead of a confusing duplicate-name list. The 0.3m tolerance is a heuristic, not a real semantic match — a building with genuinely low floor-to-floor heights (e.g. a mezzanine 0.3m above a slab) could have two real levels incorrectly merged into one row. Not expected to bite in practice, but not provably safe for all buildings.
Single SheetBoard/viewport-swap keeps the Sheet View pane structurally simple — no new sheet-management UI needed. Per-level "far" clipping distance (floor-to-floor gap to the next level up) means the topmost level ("Roof") has no next level to measure against — needs an explicit fallback default (matching today's hardcoded far = 4), which is itself still a heuristic guess for buildings with an unusually tall top floor.
