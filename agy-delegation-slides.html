01 / Project Context

BIMBOY-Platform architecture and development roadmap

Centralized Digital BIM Management Platform built on top of the ThatOpen ecosystem. Integrates 3D BIM models, documentation, spatial coordination, and GIS data into a single web platform.

  • Core & Routing: React 19, @tanstack/react-router (file-based)

  • Styling & Engine: Tailwind v4, Three.js ^0.182
  • BIM Kernel: @thatopen/components + @thatopen/ui (pinned to v3.4.x)

03 / Execution Mechanisms

How Claude Code invokes the local agy executable binary

Binary Path: C:\Users\...\AppData\Local\agy\bin\agy.exe
Shape A: Direct Workspace Writer

agy modifies or writes project files directly in place. 

agy -p "<task>" \
  --model gemini-3.1-pro-high \
  --mode accept-edits \
  --dangerously-skip-permissions

* --dangerously-skip-permissions is required in headless mode to prevent stdin lockups on permission prompts.

Shape B: Stdout Capture (Safer Default)

agy returns text output; parent captures stream to target file. 

agy -p "<task, raw HTML only>" \
  --model gemini-3.1-pro-high \
  --print-timeout 8m > deck.html

✔ Used to produce this deck. Shape A was safely rejected by Claude Code's security classifier to protect uncommitted work.

04 / CLI Parameter Reference

Essential flags for controlling agy headless execution

Flag / Option Functional Purpose in Delegation Pipeline
-p / --print Executes a one-shot prompt and prints the final response directly to stdout for parent capture.
--output-format Specifies output structure: text, json, or stream-json for programmatic parsing.
--json-schema Forces agy output to adhere strictly to a JSON Schema provided by the parent process.
--model Selects the targeted model engine for the task (Gemini, Claude, or OSS models).
--mode Controls mutation access: plan (read-only analysis) vs accept-edits (file writes).
--dangerously-skip-permissions Bypasses interactive prompt checks during unattended non-interactive execution.
--sandbox / --add-dir Configures execution containment and explicitly scopes additional directory paths.
-c / --continue Resumes a prior conversation session using a stored conversation ID.

07 / System Guardrails & Risk Mitigation

Four primary failure modes and technical counter-measures

Risk 1: Unsupervised Mutation
Mitigation: Prefer stdout capture (Shape B) so agy lacks write access. If file writes are required, take a pre-snapshot and verify with git status --porcelain.
Risk 2: Architecture Rule Blindness
Mitigation: agy does not read CLAUDE.md. Claude Code manually injects explicit rules (e.g. `@/*` aliases, no Supabase in views/) into every prompt.
Risk 3: Workflow Bypass
Mitigation: Delegation slots strictly inside the implement step of the plan → approval → implement → review cycle, never around it.
Risk 4: In-flight Code Clobbering
Mitigation: For risky or multi-file modifications, execute agy inside a throwaway git worktree and selectively cherry-pick surviving changes.

08 / Pragmatic Applicability

Evaluating when delegation creates leverage versus overhead

Good Fits (High Leverage)
  • Self-contained Artifacts: Independent documents, single-page tools, slide decks.
  • Mechanical Breadth: Repetitive structural refactorings across numerous disconnected files.
  • Independent Diagnostics: Seeking an un-biased second opinion from a different model family on complex bugs.
Bad Fits (High Risk / Low Return)
  • Deep Context Tasks: Features requiring intricate knowledge of BIMBOY architectural conventions.
  • In-Flight Branches: Working on active, heavily mutated uncommitted worktrees.
  • Cohesive Diff Ownership: Core logic changes requiring a single coherent author style.

📌 The Golden Rule: "Claude orchestrates and owns the diff. agy supplies labour. The developer owns the commit."
